# IP 地址与 VLAN 规划规范

发文单位：网络架构组  
文号：INFRA-STD-2025-004  
文件性质：技术标准

## 第一章 地址规划

**第一条** 为规范 IP 地址与 VLAN 规划，避免地址冲突与规划混乱，制定本规范。

**第二条** 子网，是指按 CIDR 划分的 IP 地址范围，是地址规划与安全策略的最小单位。子网划分应当预留不少于 30% 的增长空间。

**第三条** VLAN，是指二层逻辑隔离域，规划时需明确用途、网段与安全等级。VLAN ID 应当在 1 至 4094 之间。

**第四条** VLAN ID 分配遵循下列区段：（一）1-99 保留给网络设备管理；（二）100-499 用于生产业务；（三）500-799 用于测试与预发；（四）800-999 用于办公与访客；（五）1000 以上为临时与项目专用。

**第五条** 子网规模按业务类型确定：网络设备管理网段使用 /29 或 /28；服务器区使用 /24；办公区按楼层使用 /24；访客网络使用 /23 并启用隔离。

**第六条** 网关地址统一使用网段内第一个可用地址（.1），保留 .2 至 .10 给网络设备与虚拟化平台。

**第七条** 生产网段不得与办公网段重叠；确需互通的，必须经由防火墙策略放行，并关联变更工单。

## 第二章 命名与登记

**第八条** 设备命名规则为「机房代码-设备角色-序号」，例如 SH01-CORE-01。设备角色缩写：CORE、AGG、ACC、FW、LB。

**第九条** 接口描述规则为「对端设备-对端接口-用途」，例如「SH01-AGG-01 Gi0/1 - 上联」。未填写描述的接口视为规划不完整。

**第十条** 新增网段必须先在地址管理系统登记，取得分配号后方可配置。未登记先配置的，视为违规变更。

**第十一条** 地址回收：设备下线或业务终止后 30 日内应当回收地址与 VLAN，回收前确认无在用的策略引用。

## 第三章 互通与安全

**第十二条** 跨 VLAN 互通必须经过三层设备转发，并在防火墙上配置相应策略。禁止在生产环境使用 VLAN 跳跃或端口镜像方式绕过策略。

**第十三条** 网络设备管理面必须独立管理 VLAN，禁止与业务 VLAN 混用。管理面应当限制源地址范围，只允许运维网段访问。

**第十四条** 访客网络必须与内网完全隔离，仅允许访问互联网；禁止访客网络访问任何内部子网。

**第十五条** 新增 VLAN 的配置变更属于重要变更，需在变更窗口内实施并验证。

**第十六条** 本规范由网络架构组负责解释，每年评审一次。
